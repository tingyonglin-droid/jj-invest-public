# 背景股價更新與報價失敗恢復設計

## 目標

股價更新完全在背景執行，移除頁首右上角的更新時間、更新按鈕與旋轉圖示。短暫報價失敗時保留上一筆成功價格並快速自動重試，避免使用者等待下一個固定更新週期或手動操作。

## 現況與根因

App 已在首次載入、回到前景及每 60 秒更新報價，但短暫失敗後只會等待下一個 60 秒週期。台灣標的目前先查詢 TWSE／TPEx，再以 Yahoo Finance 備援；當所有來源都暫時失敗時，API 會把該標的回傳為錯誤。前端隨即用含錯誤的整批結果取代既有報價，因此原本可用的價格與計算也會一起失效。

畫面右上角雖標示「自動更新」，仍提供可點擊的手動更新鍵，造成使用者必須介入才能快速恢復的感受。

## 使用者體驗

- 頁首只保留品牌識別，完整移除右上角更新資訊區塊。
- 更新全程在背景執行，不顯示載入動畫，也不阻擋其他操作。
- 首次開啟、切回 App、瀏覽器重新連線，以及每 60 秒固定週期都會觸發更新。
- 若部分標的暫時抓價失敗，但 App 已有該標的的成功價格，繼續用舊價格顯示與計算。
- 失敗後依序等待 2 秒、5 秒、15 秒重試；任一次成功即停止該輪重試並恢復正常週期。
- 有舊價格可用時，不顯示來源端的原始 404 訊息。三次快速重試都失敗後，顯示溫和的「部分價格暫時無法更新，將自動重試。」提示；下一次正常觸發仍會嘗試更新。
- 若某標的從未成功取得價格，保留現有明確錯誤提示，且不以未知價格進行投資計算。

## 資料流程

1. 更新請求沿用既有 `/api/quotes`，不新增資料供應商或資料庫。
2. 每次回應以標準化代號比對現有成功報價。
3. 新回應成功的標的使用新價格；失敗標的若有舊成功價格，保留舊資料並記錄為暫時過期；若沒有舊價格，保留錯誤。
4. 合併後的報價用於既有資產、Beta 與再平衡計算。
5. 只有完整成功的更新才更新「最近成功更新」的內部時間，供歷史快照等既有流程使用；頁面不顯示此時間。
6. 若回應存在暫時失敗，啟動單一重試序列。新的更新觸發或元件卸載時，取消舊計時器，避免重複請求與卸載後更新狀態。

## 更新政策

更新觸發條件集中在自動更新模組：

- 頁面已完成本機資料載入。
- 至少存在一個持股代號。
- 頁面可見，且沒有正在進行的報價請求。

固定 60 秒更新、視窗 focus、visibility 變為 visible、瀏覽器 online 事件皆使用同一套條件。快速重試同樣不允許請求重疊，但不需等待下一個固定週期。

## 錯誤處理

- 整個 API 請求失敗：若已有成功報價，保留全部舊資料並進入快速重試；若尚無資料，顯示現有請求錯誤。
- 部分標的失敗：逐筆保留可用舊價，不讓單一資料源錯誤使整個投資組合失效。
- 匯率失敗：若已有上一筆有效 USD/TWD 匯率，採相同保留與重試原則；若沒有有效匯率，美元資產維持不可計算。
- 重試耗盡：停止快速重試，保留資料與溫和提示，等待下一個固定週期、回到前景或網路恢復。

## 實作邊界

- 不更換或新增行情資料供應商。
- 不宣稱提供交易所等級即時串流；維持目前輪詢式更新。
- 不更動持股、資產、Beta、再平衡或歷史快照的計算公式。
- 不保存過期狀態到使用者設定；重新載入後仍以首次請求結果為準。
- 不保留任何手動更新入口。

## 測試與驗收

- 單元測試鎖定重試延遲為 2、5、15 秒，以及可見、閒置、有代號時才能自動更新。
- 報價合併測試涵蓋成功覆蓋舊值、部分失敗保留舊值、首次失敗維持錯誤，以及舊匯率保留。
- UI 測試確認頁首不存在更新時間、更新按鈕、更新圖示及「更新價格」無障礙按鈕。
- UI／整合測試確認 focus、visibility、online、60 秒週期與快速重試會觸發更新，且不產生重疊請求。
- 測試確認有舊價的 404 不直接顯示，重試耗盡才出現溫和提示；沒有舊價時仍顯示明確錯誤。
- 執行完整測試與 lint，確認既有投資計算和頁面功能未回歸。
