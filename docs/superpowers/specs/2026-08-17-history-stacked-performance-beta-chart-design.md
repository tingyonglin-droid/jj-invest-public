# 歷史頁績效與 Beta 上下合併圖設計規格

日期：2026-08-17

## 目標

將歷史頁目前以分頁切換的「績效」與「Beta」曲線改為同時呈現的上下雙圖，讓使用者能沿著同一時間軸直接比較投組績效與 Beta 變化，不必切換圖表。

## 已確認的畫面結構

1. 移除「績效／Beta」切換列。
2. 同一卡片內垂直排列兩張曲線圖：
   - 上方：績效。
   - 下方：Beta。
3. 兩張圖使用完全相同的日期資料與 X 軸位置，確保每一天上下對齊。
4. 日期刻度只在最下方的 Beta 圖顯示一次；績效圖不重複顯示日期。
5. 每張圖保留自己的 Y 軸刻度，避免百分比績效與 Beta 使用錯誤的共同尺度。
6. 績效圖保留「投組」與「0050」兩條線及圖例；Beta 圖顯示「投組 Beta」曲線與圖例。

## Zoom 控制

1. 原本的「7天／30天」控制改為與市場水位相同的 Zoom 樣式。
2. 選項為 `1M / 3M / 6M / 1Y`。
3. 預設選取 `1M`。
4. Zoom 控制同時套用到績效與 Beta，兩張圖不允許選擇不同期間。
5. 控制列右側顯示目前資料的起訖日期。
6. 期間依所選月份／年份從最新資料日期向前計算，而非固定筆數。

## 同步互動

1. 使用者在任一張圖移動游標或觸控時，兩張圖顯示同一日期位置的垂直參考線。
2. 同時標示該日期在績效圖與 Beta 圖上的資料點。
3. 全部數值收在一個提示框，內容包含：
   - 日期。
   - 投組績效。
   - 0050 績效。
   - 投組 Beta。
4. 提示框與參考線共用同一個選取日期狀態，避免上下圖顯示不同日期。
5. 游標或觸控離開圖表範圍後，參考線、資料點與提示框一起隱藏。

## 資料與例外狀態

1. 兩張圖必須由同一份依日期排序、依 Zoom 篩選後的歷史資料建立。
2. 日期缺口不補造資料；現有日期依真實時間比例對齊。
3. 若所選期間內不足兩筆有效資料，顯示現有的圖表資料不足提示，不繪製不具意義的曲線。
4. 個別 0050 數值缺漏時，不影響投組績效與 Beta 顯示；0050 曲線在缺漏處中斷，提示框將該值標示為無資料。
5. Zoom 切換後若提示框正在顯示，先清除選取狀態，再依新期間重繪兩張圖。

## 響應式與視覺一致性

1. 桌面與手機版都維持上下排列，不改成左右並排。
2. 兩張圖使用相同的繪圖區左右邊界，確保時間軸垂直對齊。
3. 手機版最多顯示適量日期刻度，避免標籤重疊；起訖日期仍需可辨識。
4. Zoom、日期範圍、字體、圓角、色彩與市場水位及現有歷史頁風格一致。
5. 延續現有投組、0050 與 Beta 的線條色彩及虛實線辨識方式。

## 驗收條件

1. 頁面載入時同時看得到上方績效圖與下方 Beta 圖。
2. 預設 Zoom 為 `1M`，可切換 `3M / 6M / 1Y`，且上下圖同步更新。
3. 任一日期在兩圖上的 X 位置一致。
4. 日期文字只出現在 Beta 圖下方一次。
5. 在任一圖互動時，兩圖出現同一條對齊的參考線，提示框同時呈現績效、0050 與 Beta。
6. 手機與桌面寬度下均無裁切、重疊或超出卡片問題。
7. 現有歷史摘要、最近紀錄與其他頁面功能不受影響。

## 測試範圍

1. 單元測試：月份／年份區間篩選、起訖日期、資料不足及缺漏數值。
2. 模型測試：上下圖共享相同日期序列與 X 軸位置，Y 軸則各自計算。
3. UI 測試：Zoom 預設值與切換、移除舊分頁、日期只顯示一次、同步互動內容。
4. 完整驗證：全部自動化測試、正式建置，以及桌面與手機視覺檢查。
